# Правила виконання лабораторних робіт

Ці правила чинні для кожної лабораторної роботи курсу. Файл лабораторної роботи додає лише артефакти, імена знімків екрана та розділи звіту, специфічні для цієї вправи. Терміном виконання лабораторної роботи є термін відповідного завдання в Microsoft Teams.

Студент читає ці правила разом із лабораторною роботою, яку виконує. Microsoft Teams не додає інших академічних норм.


## Права на робочій станції

Кожен студент Windows у цьому курсі працює з обліковим записом локального адміністратора. Команди лабораторних робіт можуть створювати каталоги, встановлювати залежності проєкту за допомогою `uv` і записувати файли в дереві репозиторію. Інструкції передбачають ці права і не адаптовані для облікових записів Windows з обмеженими правами. Студентам Linux і macOS потрібні еквівалентні права на встановлення залежностей і запис у дереві репозиторію.

## Зміст звітів

Звіт відображає роботу, виконану під час лабораторної роботи, а не лише остаточні результати. У звіті детально описано хід виконання, щоб інший читач міг відтворити, що було зроблено, у якому порядку і чому.

Наданий `REPORT.md` є інструктивним шаблоном. Початкові вказівки та підказки в розділах визначають, який зміст має написати студент; вони не є змістом звіту. Перед поданням студент замінює або вилучає кожну інструктивну підказку, але зберігає всі надані заголовки звіту.

Звіт є формальною технічною документацією. У ньому використовують конструкції третьої особи або безособові конструкції та не використовують виклад від першої особи, зокрема `я`, `ми`, `мною`, `нами`, `мій`, `наш` або рівнозначні форми. Наприклад, у звіті пишуть «студент виконав перевірку», «перевірку виконано» або «результат підтверджує», а не «я виконав перевірку» чи «ми отримали результат».

Кожен звіт має містити розділ `Мета роботи` на початку та розділ `Висновки` наприкінці. У розділі `Мета роботи` сформульовано бажану спроможність або стан системи з лабораторної роботи, а не перелік дій. У розділі `Висновки` зазначено, що студент виконав і які результати отримано, а також прямо визначено, чи досягнуто мету повністю, частково або не досягнуто. Це визначення має спиратися на наведені у звіті свідчення. Якщо мету досягнуто частково або не досягнуто, у висновках також названо відсутній результат і його причину.

Кожен звіт містить заголовок `Хід виконання` між `Мета роботи` та `Висновки`. Підрозділи контрольних точок ідуть у порядку опублікованих кроків студента, пояснюють виконану дію, спостережений результат і підставу для продовження та містять знімок екрана, названий лабораторною роботою для відповідної контрольної точки. Позначення, які використовувалися лише під час розроблення матеріалів курсу, зокрема `Authoring Stage B`, `C1` або `C2`, не є етапами виконання роботи студентом і не повинні з’являтися у звіті.

Звіт без будь-якого з обов’язкових розділів, без прямого визначення ступеня досягнення мети у `Висновках` або з викладом від першої особи є неповним і повертається на виправлення.

У звіті наведено всі обов’язкові знімки контрольних точок, названі в цій лабораторній роботі, включно зі знімком остаточної перевірки. Кожен знімок однозначно ідентифікує автора та дату створення: на зображенні видно обліковий запис операційної системи або GitHub і системну дату (`Get-Date` або `date` в тому самому терміналі, або видимий годинник). Підпис у звіті не замінює цієї видимої ідентифікації. Знімок екрана фіксує власне виконання роботи студентом; авторська ілюстрація, скопійований вивід або зображення-заповнювач не є знімком контрольної точки.

Поданий пакет ідентифікує форк студента на GitHub, особисту гілку та повний хеш коміту. Зазвичай усі три значення наведено в розділі ідентифікації звіту. Якщо конкретна лабораторна робота прямо використовує перевірку після коміту і тому не може помістити власний хеш коміту в цей коміт, зафіксований вихідний звіт містить форк і гілку, а згенеровані свідчення перевірки містять повний остаточний хеш. Окреме супровідне повідомлення або заповнення текстового поля Microsoft Teams не потрібне; студент додає лише файли, перелічені в лабораторній роботі.

Звіт обсягом однієї сторінки не може бути оцінений на високий бал.

Поданий наративний звіт пишеться українською мовою.

## Подання звітів

Звіти завантажують у відповідне завдання Microsoft Teams. Наративний звіт є одним файлом Markdown із назвою `REPORT.md`. Файл вкладено безпосередньо; посилання не є поданням.

Лабораторна робота може також вимагати невеликий набір машиночитних файлів-свідчень. Ці файли додають окремо. Архів не приймається.

Вихідний звіт у Git використовує відносні шляхи зображень Markdown до `reports/labNN/screenshots/`; саме цей звіт переглядають на GitHub. Наративний файл для Teams є копією, яку створює `learning-project prepare-report`: команда вбудовує зображення, щоб Teams міг відобразити один вкладений Markdown-файл. Студент запускає цю команду так, як записано в лабораторній роботі. Згенерований `reports/labNN/submission/REPORT.md` є ігнорованим вкладенням Microsoft Teams і не фіксується у форку.

## Академічна доброчесність

Звіти, що містять ознаки плагіату, списування або є ідентичними роботам інших студентів, до заліку не приймаються.

Використання задокументованого в курсі шляху агента для чернетки пропозиції лабораторної роботи не є плагіатом. Копіювання звіту, знімків екрана або машиночитних артефактів іншого студента є порушенням.

## Фіксація результатів

Після успішного захисту всіх лабораторних робіт наприкінці семестру оцінки буде перенесено у файл обліку навчальної групи.

## Дотримання термінів виконання

Для кожної лабораторної роботи встановлено термін виконання: дату здачі відповідного завдання в Microsoft Teams. Порушення цього терміну знижує оцінку на 1 бал. Роботи, подані пізніше залікового тижня, можуть бути розглянуті в наступному семестрі.

Приймання робіт здійснюється по одній лабораторній роботі за раз.
